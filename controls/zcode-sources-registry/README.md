# Реестр источников и моделей — происхождение материалов

Поручение CORE 31.10 п.6 (zcode-m5m). Реестр фиксирует происхождение
учебных материалов и моделей ДО любой загрузки: revision/SHA, лицензия,
права на upstream-код, источник метки, coverage, usage (train/eval-only),
политика дубликатов.

## Что здесь

- `sources_registry.json` — машиночитаемый реестр: 10 источников + 5 моделей.
  Все revision — реальные git-commit SHA на 31.10 (GitHub API) либо версия
  документа; digests моделей — реальные sha256 из локального реестра ollama
  на M5M. Никаких выдуманных байтов.
- `manifest_check.py` — исполняемый валидатор гейтов replit.
- `test_manifest_check.py` — тесты гейтов + самозачёт реестра.

## Команда

```bash
python3 manifest_check.py                      # самозачёт реестра
python3 -m unittest test_manifest_check -v     # тесты гейтов (16)
```

## Гейты (следит валидатор)

1. **Обучение заблокировано без ревью:** `usage=train*` требует
   `license_reviewed=true` и `upstream_code_rights != unknown`.
   Лицензия README репозитория НЕ означает права на всё содержимое корпуса
   (replit 31.10) — у каждого источника свои upstream-права.
2. **Опасные секции — принудительно eval-only** (`dangerous_sections=true`):
   CyberSecEval insecure-code samples, CTF-задачи Cybench. Авто-скачивание
   и исполнение в рабочем окружении запрещены.
3. **Исполнение запрещено:** допустимые execution_rule — `no-exec`,
   `no-remote-code`, `verified-runtime-only`. Датасеты — данные, не код;
   код моделей исполняется только через проверенный runtime (ollama).
   Discovery/router НЕ переключается на исполнение неподтверждённого кода
   модели.
4. **Модели с digest или никак:** у каждой модели sha256 digest; LoRA-кандидат
   обязан зафиксировать совместимость основы и токенизатора.
5. **HF-ключи не нужны** (зафиксировано с обоснованием): на 31.10 в реестре
   нет закрытых/gated поставок. Ключ запрашивается только при включении
   реально gated поставки после письменного обоснования; credentials не
   печатаются и не коммитятся.

## Известные gaps (честно)

- **primevul**: лицензия датасета (в отличие от кода) в README не найдена —
  `license_reviewed=false`, usage занижен до `eval-only`. Повышение до
  train — только после ревью.
- **owasp-genai-top10** и **purplellama-cyberseceval**: лицензия не
  распознана автоматически (NOASSERTION) — ручное чтение LICENSE перед
  любым включением в корпус.
- Wycheproof применимые наборы перечислены (aes_gcm, chacha20_poly1305,
  ecdsa, eddsa, rsa_signature, x25519, hkdf) — конкретные json-файлы
  фиксируются по sha256 при включении в миссии K1/K3/K4.

## Порядок работы с реестром

1. Новый источник → запись с pinned revision/SHA/лицензией/правами.
2. `python3 manifest_check.py` — PASS обязателен.
3. Только метаданные до отдельного решения; размер и формат архива
   проверять до распаковки; install hooks и remote code — никогда.
4. Обучение на источнике — только когда валидатор пропускает train.
